# Domain documentation

RelayOps uses one domain context. Shared terminology belongs in GLOSSARY.md at the repository root. Accepted architecture decisions belong in docs/adr/.

Before exploring a domain area, read the glossary if it exists and any ADRs relevant to that area. If these files do not exist, continue without creating placeholders. Use the domain-modeling skill to record terms and decisions when they are resolved.

Use the glossary's terms in tickets, code, tests, and reports. Raise ambiguous or overloaded terms before defining a competing meaning. If a proposal conflicts with an accepted ADR, name the conflict and explain why the decision should be revisited.

Proposed review decisions remain proposals until the owner accepts them. Keep implementation status and measured results distinct from plans.
