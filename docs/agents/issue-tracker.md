# Issue tracker

Specs and implementation tickets live in GitHub Issues at https://github.com/nathan-thong/RelayOps. Use the gh CLI from this checkout, or specify --repo nathan-thong/RelayOps.

Read a ticket and its comments before working on it. Use descriptive titles and link related decisions, acceptance criteria, and blockers. When a skill says to publish a spec or ticket, create a GitHub issue.

Pass multiline issue and comment text through --body-file. Write the exact text to a temporary file first. Follow the user's authorization for posting and other external writes; installing a skill does not authorize messages.

Use open/closed issue status for progress and native issue dependencies for blockers. Where dependencies are unavailable, use a Blocked by line with real issue links. Refer to issues by linked title when reporting to the owner.

PRs as a request surface: no.

The routine workflow uses bug and enhancement only. Wayfinder has not been configured; if the owner later invokes it, adapt its map and ticket conventions to this repository before creating extra labels or tracker structures.
