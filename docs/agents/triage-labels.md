# Issue labels

The owner chose two category labels for this solo project:

| Label | Use |
| --- | --- |
| bug | Existing behavior is broken. |
| enhancement | A new capability or improvement is proposed. |

Use the applicable category for a bug report or feature request. Planning and decision issues can remain unlabeled. GitHub's other default labels may exist; they are outside this project's routine workflow.

The five state labels assumed by the upstream triage skill are disabled here. Keep progress in issue status, dependencies, and brief notes:

| Upstream role | Project convention |
| --- | --- |
| needs-triage | Leave open; review the issue and its existing notes. |
| needs-info | Leave open and record the unanswered question. |
| ready-for-agent | Record an agreed scope and acceptance criteria; work only when blockers are resolved. |
| ready-for-human | Record the decision or manual step the owner needs to take. |
| wontfix | Record the rejection reason and close when authorized. |

These are workflow conventions, not label aliases. Do not map state roles onto bug or enhancement, create state labels, or infer task readiness from a category label. This owner-approved convention overrides the upstream requirement for one state label on each issue.
